# Threat model

The system holds biometric data (face images and embeddings) of real people, which falls under India's DPDP Act 2023. Gaps are listed plainly below.

| Actor                            | Entry point                                      | Worst realistic abuse                                                                          | In place                                                                                  | Gap                                                                                                                                                   |
|----------------------------------|--------------------------------------------------|------------------------------------------------------------------------------------------------|-------------------------------------------------------------------------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------|
| Client's own containers          | `/ingest` :20001                                 | Forge or flood attendance records                                                              | Not published on the host (D-036)                                                         | No auth                                                                                                                                               |
| Client's own containers          | `/faces` :8000                                   | Inject face crops that feed the staging collection, so a person can be matched as someone else | Not published on the host (D-036)                                                         | No auth                                                                                                                                               |
| Anyone on this host              | `/post_images` :20013, CORS `*`                  | Read portraits of anyone by ID                                                                 | 127.0.0.1 only (D-040)                                                                    | No auth                                                                                                                                               |
| Anyone on the LAN                | Milvus :19530                                    | Read, change or delete all embeddings                                                          | Per-client users confined to their own database; root's default password replaced (D-037) | No TLS; the admin password lives in the deploy folder's `admin.env`                                                                                   |
| Anyone on the LAN                | Milvus MinIO :9000/:9001                         | Same, with default `minioadmin` login                                                          | Nothing                                                                                   | Default credentials                                                                                                                                   |
| Anyone on the LAN                | Kafka :9092, SCRAM                               | Fake display messages, read who was recognised                                                 | SCRAM login per client, ACLs by topic prefix, read-only display logins; plaintext only on the broker's loopback; unused add-ons removed (D-037)| SASL_PLAINTEXT: authenticated, not encrypted; one display login per client, not per screen                                                            |
| Anyone on the LAN                | Postgres port                                    | Read everything, given the password                                                            | One role per client owning only its databases; `CONNECT` revoked from `PUBLIC` (D-037)    | No TLS; the admin login is a superuser on the host                                                                                                    |
| Anyone on the LAN                | InsightFace :6385                                | Use the GPU, deny service                                                                      | Nothing                                                                                   | No auth                                                                                                                                               |
| Anyone on this host              | ROI page :8069 (profile roi, only while started) | See camera snapshots, change any camera's region                                               | Listens on 127.0.0.1 only, off by default, validates points, writes the config atomically | No login; stop it after use                                                                                                                           |
| Anyone with a login or token     | API :9090                                        | Read all attendance and frames                                                                 | HTTPS proxy; scrypt passwords, roles, CSRF, throttling, expiring and revocable sessions and tokens (D-039, D-040)| The private CA's key is on the host                                                                                                                   |
| A person at a camera             | Camera                                           | Hold up a photo to be marked present                                                           | Liveness code exists                                                                      | Liveness is off (`ENABLE_FACE_LIVENESS_DETECTION = False`)                                                                                            |
| Insider                          | Dataset store :9010                              | Copy all face images                                                                           | Own login, separate from Milvus; one bucket and access key per client (D-037)             | DVC still uses the root login; no encryption at rest beyond BitLocker                                                                                 |
| Client host administrator        | Docker images and the deploy folder on the host  | Copy our source code: the images hold readable Python                                          | Hosts pull images and a source-free bundle (D-033)                                        | Images still hold `.py` until they are compiled; the deploy clone and the owner's `gh` login remain until the watcher moves to the registry (next PR) |
| Compromised dependency           | Images, packages                                 | Code runs in every service                                                                     | Pinned versions and digests, Dependabot, gitleaks                                         | 9 open Dependabot alerts at last count, not triaged; `pgsty/minio` is a community fork                                                                |
| Compromised PR or GitHub account | CI, releases                                     | Malicious code merges and deploys itself to this host, with no human review (D-025)            | CI checks; automerge runs only from `main`, skips forks, and needs every check to pass    | Nothing beyond CI stops it                                                                                                                            |
| Someone with this laptop         | Disk                                             | Everything                                                                                     | Windows login                                                                             | `.env` is plain text in two folders                                                                                                                   |

Worst first, what to close:

1. Publish less. Since D-036 step 2 each client's stack has its own network and publishes only the API and what displays need; `/ingest`, `/faces` and the feedback port are internal. The shared services (Milvus, its MinIO, Kafka, PostgreSQL, InsightFace) still listen on the LAN until step 3 adds logins.
2. Add a key to `/ingest`, `/faces` and `/post_images`.
3. Change the Milvus MinIO credentials. Milvus authentication and per-client logins on every shared service are in place since the D-037 cutover (docs/CUTOVER-D037.md).
4. Move the API key from the query string to a header.
5. Triage the Dependabot alerts.
6. Add a deletion path for one person across images, Milvus and Postgres (see [DATA.md](DATA.md)).
